# Правило публикации новостей на Solargy.kz

Статус: проект правила, подготовлен по результатам анализа. До согласования настройки Битрикс не изменяются.

## Почему нужен смешанный подход

У старых новостей поле «Описание для анонса» часто пустое. У новых материалов оно заполняется содержательным текстом. Поэтому нельзя сразу заменить общий шаблон description на `{=this.PreviewText}` для всего инфоблока: старые страницы могут остаться без описания.

## Заполнение новой новости

1. **Название** — уникальное и понятное без просмотра текста статьи. Рекомендуемая длина: примерно 45–80 знаков.
2. **Описание для анонса** — 1–2 предложения по сути материала, без HTML, приветствий и повторения заголовка. Ориентир: 120–180 знаков.
3. **SEO title** — по умолчанию оставить наследуемый шаблон `{=this.Name} — SOLARGY Казахстан`. Ручное значение задавать только когда заголовок слишком длинный или нужен иной поисковый акцент.
4. **SEO description** — для новой качественной статьи задать индивидуальное описание на SEO-вкладке на основе анонса. Оно должно описывать пользу страницы, а не перечислять ключевые слова.
5. **Заголовок страницы H1** — оставить равным названию материала, если нет обоснованного исключения.
6. После публикации проверить публичные `title`, `description`, H1 и canonical.

## Старые новости

- Не менять массово.
- Если анонс пустой, оставить текущий наследуемый шаблон как безопасное резервное описание.
- Индивидуально дорабатывать только страницы с поисковым трафиком, важные посадочные материалы и реальные дубли после нового обхода Яндекса.

## Запрещённые варианты

- один и тот же description для разных новостей;
- список ключевых слов вместо связного описания;
- копирование первого абзаца вместе с HTML или служебным текстом;
- изменение глобального шаблона без проверки старых материалов;
- массовое редактирование только ради устаревшего отчёта Вебмастера.

## Контроль после публикации

- метатеги уникальны;
- title соответствует теме и не обрывается смыслово;
- description понятен человеку и соответствует странице;
- canonical указывает на текущий URL;
- страница доступна для индексации;
- ключевая новая страница при необходимости отправлена на переобход.
